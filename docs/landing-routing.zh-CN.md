# 香港入口的 AI 分流

在香港 J-UI 的“配置落地机”中启用分流后，所有已启用、未绑定专用出口的常规入站协议自动纳入。新建或启用的常规入口会在下次重生成配置时自动加入；显式绑定其他出口的入口和临时住宅节点继续使用各自的路由。旧版已经保存的单入口配置不会在升级时自动扩大范围：需在新版面板点击“保存并应用”才切换到全常规入口。先在面板中填写公网 IPv4（可选）、公网映射端口、本机监听端口及 Reality SNI，点击“生成一键脚本”，审查后把完整脚本复制到目标落地 VPS，以 root 执行；无需再另输参数命令。修改参数会使旧生成结果失效，需重新生成。脚本下载并 SHA-256 校验固定版本 sing-box 1.14.0，建立独立账户、配置目录与 `j-ui-landing.service`，不会覆盖 J-UI 或 Xray 默认服务。普通公网 VPS 默认使用 TCP 14443；脚本需要 Linux amd64/arm64、systemd、curl、openssl、ss 等基础工具；私钥只保留在落地机。

NAT VPS 必须按服务商给出的映射填写：例如公网 TCP `10086` 转发到落地机本地 TCP `14443`，在面板中分别填入两个端口，生成完整脚本后运行；如果公网和内网端口相同，就把两个字段设为同一个端口。脚本输出的 `ADDR`、`PORT`、`UUID`、`PUB`、`SID`、`SNI` 六行粘贴进香港面板。`PORT` 必须是香港可访问的公网端口，不能填仅在 NAT 宿主机内部可见的端口。可使用 `ADDR=<公网IPv4>` 显式指定地址；自动查询到的地址也必须核对。如果没有 TCP 入站端口映射，不能直接使用这条 TCP 第二跳，需要服务商中转或其他隧道。如果落地机公网 IP 后续轮换，须重新在面板中提交新地址，否则香港机仍会连接旧地址。新增配置使用这六行中性字段；后端仍兼容旧版 `JP_*` 字段，不再接受 VLESS Reality URI 导入；已保存的旧配置仍可读取。客户端仍只连接香港节点。HY2 不用于第二跳；当前引导只导入 VLESS Reality (TCP)。

香港 sing-box 在纳入范围的入口嗅探 HTTP、TLS 和 QUIC：强制原生直连规则优先，其次强制落地规则，再按 V2Fly `category-ai-!cn` 快照匹配 AI 域名；其他流量使用香港 `native` 出站。落地出站失败时，已命中的连接不会回退到香港。域名不可见（例如仅有目标 IP 或加密客户端握手）时不能保证 AI 命中；服务器无法识别本地程序名称，电脑端仍需确保应用流量进入香港节点。

内置规则基线来自 `v2fly/domain-list-community` 提交 `bcea25493ed28c387660fe49ce1ceb242d2efca0`，仓库副本位于 `internal/engine/singbox/ai-rule-set.json`；原项目 MIT 许可见同目录 `AI-RULES-LICENSE`。规则管理页可以输入 GitHub Raw 的 sing-box JSON 地址并点击“更新规则集”；示例地址是 MetaCubeX 提供的 AI 分类规则 JSON。更新仅在手动点击时执行，不会定时抓取。URL 限制为 `https://raw.githubusercontent.com/.../*.json`，不跟随重定向；下载限制 1 MiB，要求仅包含一组非空域名规则。下载和验证失败不会改变现有规则；成功后记录来源、时间和内容哈希，重新生成、检查并应用配置，失败时回滚。点击“恢复内置规则”可恢复随程序打包的快照。另可按域名后缀增补“强制落地”和“强制原生直连”。来源版权和许可需由操作者确认。

落地连接信息仅用于一次性提交，并以实例密钥加密保存；GET API 不回显 UUID。脚本输出含连接凭据，不能公开分享；终端历史或剪贴板也需妥善保护。面板中六行 `ADDR`、`PORT`、`UUID`、`PUB`、`SID`、`SNI` 是连接信息字段；后端兼容旧版 `JP_*` 字段。“未配置/未启用”状态以服务器返回值为准。上线前应分别在香港 VPS 上检查 `sing-box check`、香港客户端默认出口 IP、AI 站点出口 IP、以及落地第二跳故障时是否阻断。配置检查和入口监听健康检查并不证明落地链路可用。
